# Repository instructions

- Target Python 3.12 and Windows x64; use PySide6 for the GUI.
- Keep application code in `src/picer`, tests in `tests`, and packaging entry points in `scripts`.
- Install with `python -m pip install -r requirements-dev.txt -e .`.
- Before committing, run `python -m ruff check .`, `python -m ruff format --check .`, and `python -m pytest`.
- In headless Linux, set `QT_QPA_PLATFORM=offscreen` for GUI tests. This does not validate a Windows EXE.
- Build the Windows binary only on Windows with `python -m scripts.build_windows` (PyInstaller `--onedir --windowed`).
- Preserve CI checks on main pushes and pull requests. Upload the complete dist/Picer folder only after tests and packaged folder/relocation checks succeed.
- Do not commit virtual environments, caches, build outputs, EXEs, or local secrets.
- Report only checks that actually ran; distinguish Linux checks, Windows CI, and manual desktop validation.

- Keep public plugin SDK compatibility in `src/picer/plugins/api.py` and `docs/plugins.md`; API v1 plugins are trusted in-process Python, not sandboxed.
- Never auto-enable user-installed external plugins. The user-authorized shipped examples are provisioned by the trusted application catalog: panels/functions on, skins off; preserve later user choices and explicit uninstalls. Revoke context, commands, subscriptions and tasks when disabling or failing a plugin.
- Plugin tests must use temporary data directories; never touch the developer's installed plugins or settings.
- Preserve the packaged EXE smoke test that installs and executes the real external example ZIP.

- Resolve resources from the application directory; never derive data paths from cwd. Keep plugins, cache, config and logs separate; preserve user settings during migrations and updates.

- New components must declare type skin/function/panel. Skin packages are declarative resources in skins; functions register exactly one command; panels register exactly one widget and dock only left/right, except a declared progress role restricted to bottom; allow at most one bottom progress overlay. Preserve explicit legacy API v1 migration support.
- Revoke quick-slot bindings and docks on cleanup. Keep exactly five top-bar slots and no bottom status bar. Test fullscreen/normal panel visibility transitions and persisted user choices.

- Scope skins to host widgets only; preserve external plugin QIcon and content styles. Fixed panels use opaque charcoal shells; only auto-hide reveals use shared glass backdrops; hover reveals must preserve hidden preferences and restore widget ownership on cleanup.
- Keep four primary example ZIPs (file browser, image info, progress, macOS skin) plus the SDK negative regression ZIP. EXE checks must read actual JPEG EXIF and exercise hover animation and persistent example settings.
- Keep default UI charcoal with a distinct lime accent; appearance settings may override the accent, and shared controls/opt-in example plugins must follow it without rewriting external QIcon or original content styles. Default example panels have no component-configuration buttons; edit component settings inline in Plugin Management. The file browser quick-settings menu is authorized for daily browsing actions. Application preferences belong in Options → System Settings.
- Preserve panel motion: 420 ms OutBack (overshoot 0.55) expansion, 300 ms InOutCubic collapse, 220 ms leave delay and continuous reversal. Visual restyling must not change these animations.
- Popup menus and comboboxes must have transparent rounded corners and no native white frame. Use RoundedSlider for default progress/settings sliders; render tests must check both orientations, inverted appearance and range endpoints while retaining Qt input behavior.
- Accent selection uses the app-owned StyledDialog HSV picker, never a platform or standard Qt color dialog. Keep HEX/RGB synchronized, invalid input blocked, cancel/follow-skin semantics and explicit application-settings save. Image drops must reach the opening pipeline from the graphics viewport and view as well as window chrome; accept only supported local files, advertise copy, preserve source files and test complete enter/move/drop sequences in normal/fullscreen modes.

- Bottom progress uses a centered one-third-width overlay and must not reserve a dock row. Side docks reach the bottom. Expose fixed/auto-hide only on grips and indicator strips. Transparent preview thumbnails retain configurable size and unrestricted total folder browsing, individual shadows, edge feathering and no scrollbar.

- File browser: neutral frosted folder icons classify direct decodable images asynchronously; keep cache/watches bounded and stop them on disable. Selected row/tile outlines encompass the whole background, never tint folder icons. Keep parent entry pinned first, directories before files in every sort direction, single-click selection and double-click folder entry. Side keys navigate history; Backspace goes up but must keep text editing intact.
- Preview reveal/compact motion shares one reversible timeline (280 ms OutCubic open, 220 ms InOutCubic close). Keep independent preview docking and existing edge-hover motion; verify intermediate frames, reversal and cleanup.

- File browser locations: Picer-only favorites and recent folders persist separately from session back/forward navigation, each bounded to 64 entries. Drive roots go up to the virtual disk list. Returning to a parent selects the exited directory and scrolls to the top. Keep folder-specific sort overrides bounded to 128 entries; normal/image-containing folder defaults are separate plugin settings, classified asynchronously without recursive scans.

- Hidden bottom progress uses a tiny transparent 24px ring (20px outer diameter); image position is the accent outer ring, animated frame position a silver inner ring. With independent thumbnails open, anchor it to their left; preserve hover/click pin controls and all motion timings.

- Held image navigation uses the saved millisecond interval, ignores OS repeats and stops on release/deactivation or editing focus. Rapid mode pauses full refinement and prefers 960px previews; use a separate bounded neighbour prefetch pool and keep stale-result/cancellation rules.
- EXIF tables stay bottom-anchored with wrapping columns and upward details expansion. Preserve original metadata SDK fields; parse RAW camera tags independently of pixel/histogram decoding and never invent missing camera/lens values.

- All thumbnails use the host ThumbnailService/ThumbnailCache via request_thumbnail; keep a shared 256px oriented master, coalesced decode, memory/disk limits, per-consumer cancellation and plugin revocation. Preview virtualizes visible neighbours without imposing a total image count cap; old thumbnail_count values are ignored. Window controls remain 32px and share the effective user accent; fullscreen precedes minimize/maximize/close.
- The hidden bottom progress ring coexists with its original 84x5 indicator; keep both hover/pin entry points, avoid overlap, clean up both and preserve existing animation timings.

- Memory thumbnail lookup must never share locks with disk encoding/scanning/eviction. Maintain the disk index incrementally; queue startup/preference trimming off the GUI thread. GIF/WebP startup reuses the playback first frame (including over-budget transient frames); warm shared memory before emitting image events and preserve EXIF orientation, cancellation and bounded playback cache. Verify both formats continue playing with blocked cache IO.

- Folder icons remain frontal, with a smaller card inset to the right behind the frosted sleeve. Select the first directly readable image by name in a background scan, then request its pixels only through the shared thumbnail SDK. Bound composites, requests and source-file watches; invalidate on first-photo edits as well as directory changes, reject stale callbacks and clean up on disable. Preserve directory-specific sorting, whole-row selection and panel motion.

- Fullscreen title/menu chrome overlays the canvas with a plain 180 ms translation and restores the normal 48px menu slot on exit; only the app icon remains at top left. Keep unrelated panel/preview motion unchanged.
- Navigation repeat defaults to a 1000 ms hold delay separate from the saved repeat interval; first press is immediate, rapid mode begins only at repeat, and release/deactivation cancels both timers.
- Input profiles support multiple keyboard/mouse/touch bindings, preserve legacy migration and disabled-plugin overrides, and explicitly offer replacement for cross-operation conflicts including keyboard prefixes. Mouse/touch runtime is scoped to the image canvas; five touch zones have no default assignments.
- Ship double-page and touch-support function ZIPs in addition to the existing examples. Double-page mode starts off, composes qualifying consecutive narrow images asynchronously, preserves pair navigation and falls back to singles for wide/last images. Touch support starts on with no assigned commands; host-owned feature permissions are revoked during cleanup.

- Every function command must have an icon before quick-slot assignment; preserve explicit external QIcon across skins and render fallback icons for disabled functions. Ship transparent PNG app artwork and seven-resolution ICO alpha/glow; retain opaque dark internal details.
- Notifications are confirmed text-only 32px frosted capsules, click/touch-through with no focus or buttons, using 140ms translation and default 1000ms dwell (configurable 250–10000ms). Bound/deduplicate pending feedback, capture only the small notification region, survive modal dialog closure and revoke timers/ownership at shutdown. Background plugin callbacks must never be mistaken for user command triggers.
- Only the example image/frame progress sliders opt into absolute left-click seeking; keep native dragging, tracking, keyboard, RTL and inverted-range behavior. General settings sliders retain their previous interaction.

- Core browser / slideshow operations use revocable panel providers, not private example-instance access. Preserve old input profile IDs while displaying explicit fullscreen toggle / enable / cancel labels; fresh enable/cancel bindings are empty. Copy actual image pixels (full resolution for still previews) with background decoding and stale-result guards.
- Sibling image-folder navigation scans only direct sibling directories off the GUI thread, skips nested-only/invalid files, respects cancellation and never wraps at boundaries. Reading direction reverses relative navigation and pair placement; absolute jumps retain file indices.
- File-browser search filters only the current level, shared by list/tiles. Random location selects a direct child without entering. Image-open synchronization selects/reveals only in the same browsed directory, respects user navigation and retains parent-return selection. Uniform panel scrollbar preferences apply to hidden/lazy views and restore original policies; never introduce information-panel horizontal scrolling.

- Gamepad bindings use optional system XInput DLLs from absolute System32 paths, fixed-width ABI fields, bounded single-worker polling and no default assignments. Native reads must not block the GUI; discard pre-transition worker results. Preserve the unbranded asymmetric diagram and neutral guide symbol; guide detection depends on an optional extended export. LB/RB/LT/RT chords reserve modifier shoulders against standalone bindings, offer explicit conflict replacement and do not fire base inputs twice. Suppress command routing during settings capture, editing, popup/modal interaction and background focus; rebaseline held inputs on reconnect/profile/capture transitions. Stop polling and detach page subscriptions on cleanup. Windows CI must exercise the real DLL and simulated packaged routing without claiming a physical controller was tested.

- Input settings use a bounded outer layout with independent command-list/form scrolling. Keep the binding list and add/remove controls visible across all four tabs; hidden form size hints must not enlarge other tabs. Package the transparent controller artwork under assets/ui and use one aspect-preserving transform for artwork, highlights and hit testing. Verify minimum/default/large dialog sizes, larger fonts and scaling in addition to input behavior.
- System Settings is a single reusable nonmodal topmost window under Options, retaining its legacy input ID. Apply saves without closing; Save closes, and Cancel only discards unapplied edits. Reset/default layout use themed confirmation with Cancel as default and only stage changes. Versioned bounded JSON backups cover application/input/skin/layout/slots, not plugin execution or enable flags; validate before editing the form and apply through the shared settings path. Preserve untouched main-window changes and close/detach settings on host shutdown. Test modeless keyboard/gamepad routing, persistence, import cancellation/errors and actual packaged transfer.
- Format selections apply across file opening/drops, directory indexes, sibling navigation and the example browser. Invalidate stale asynchronous indexes on changes while preserving existing pixels/caches. Keep the canvas context menu styled and respect explicit right-mouse bindings. Windows integration is explicit, per-user HKCU registration for the packaged EXE, with quoted absolute commands and reversible Picer-only Explorer keys; never modify UserChoice, other applications or HKLM. Default-viewer registration must open Windows Default Apps for user confirmation. Verify registration against isolated native HKCU roots in Windows tests and the relocated EXE, cleaning every test root.
- Host layout containers are transparent by default; paint opaque backgrounds only on explicit surfaces so rounded children never reveal rectangular backing. Combo popup containers must disable native QFrame borders as well as enable alpha; verify real settings dropdowns and hovered input tabs, all menu levels, plugin controls and alternate skins. Do not reintroduce the removed static animation/rotation/docking explanations as settings cards.

- Build production Inno Setup installers only on Windows from the verified complete portable folder. An explicitly isolated compiler-test payload may be compiled for preflight only, never installed or published. Install per user without elevation; context-menu/default-viewer tasks are opt-in. Never write UserChoice, other default associations or HKLM. Open Windows Default Apps only after an explicit selected task and never during silent verification. Preserve config/plugins/skins/cache/logs on upgrades and uninstall; remove only registration commands/icons still owned by this executable path. Test the public installer and real installed EXE, upgrade/restart/uninstall, all integration combinations in isolated native HKCU, and preservation of another Picer copy's registrations.
- Keep portable ZIP and installer EXE together with SHA256SUMS in release-assets (never commit generated artifacts). Release publication requires explicit authorization and a main commit marked [release]; only the dedicated contents:write release job may publish after all Windows/build/installer checks pass. Upload to a draft first, then publish. Ordinary pushes and PRs must not publish releases.
